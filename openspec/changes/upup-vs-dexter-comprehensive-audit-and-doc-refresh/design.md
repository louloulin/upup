## Context

UpUp (涨涨) is a fork of [virattt/dexter](https://github.com/virattt/dexter). The upstream dexter README (192 lines) and code (184 src files / 21,899 lines TS+TSX) position the project as a CLI-based deep financial research agent for US markets. UpUp's fork has grown 10.9× in code volume (1,055 src files / 237,914 lines) and added 18 workspace packages (1253 files / 406,495 lines total) targeting A-shares / HK / global markets, Chinese-language workflows, multi-agent collaboration, plugin ecosystems, and Session 2.0 architecture. The "Chinese version of dexter" claim is the foundation of the brand, but it currently lives in scattered, sometimes-stale prose across 8+ docs.

This change makes that positioning **one authoritative audit + one white paper + a clear refresh of 7 supporting docs**, so any reader (user, contributor, investor, journalist) gets the same story from the same numbers.

## Goals

1. **One source of truth for "upup vs upstream"**: `docs/upup-vs-dexter-audit.md` (in this change's `docs/` folder) becomes the only place that asserts the comparison numbers.
2. **One white paper for the China-edition positioning**: `docs/upup-china-edition-positioning.md` is the only place that formally states what the China edition is and what it is not.
3. **Refresh, don't rewrite**: keep the strong existing docs (README, README_CN, AGENTS, comparison, positioning, COMPETITIVE); trim duplication and link to the audit/white paper.
4. **No code change**: the change set is documentation-only; no `src/`, no `packages/`, no `package.json`, no API.
5. **Reproducible audit**: the new spec `upup-vs-dexter-audit-spec` codifies the methodology so the audit can be regenerated by CI later.

## Non-Goals

- Re-litigating the technical architecture (covered by archived `top-tier-investment-assistant` and in-progress `upup-vs-loucode-gap-audit-and-roadmap`).
- Adding new features, new skills, new commands.
- Translating any new code; this change is docs-only.
- Changing the version, branch, or release cadence.

### Audit methodology (codified in `upup-vs-dexter-audit-spec`)

| Dimension | Metric | Data source | Cadence |
|---|---|---|---|
| Code volume | `find src -type f \( -name "*.ts" -o -name "*.tsx" \) \| wc -l` + `wc -l` | upup HEAD, dexter HEAD | on change |
| Tool count | `find src/tools -type f -name "*.ts" \| wc -l` | upup HEAD, dexter HEAD | on change |
| Skill count | `find src/skills -name SKILL.md` + bundled/ | upup HEAD, dexter HEAD | on change |
| LLM providers | `packages/llm/src/` enum + `src/model/llm.ts` | upup HEAD, dexter HEAD | on change |
| Workspace packages | `ls packages/` | upup HEAD, dexter HEAD | on change |
| Investment commands | `src/commands/investment/*.ts` | upup HEAD | on change |
| Runtime adapters | `src/plugins/adapters/*.ts` | upup HEAD | on change |
| i18n keys | `src/i18n/strings.ts` key count | upup HEAD | on change |

Each dimension produces a single reproducible command whose output is committed to the audit doc as a code block. The audit doc is dated (`Audit generated: 2026-06-12`); the spec defines when regeneration is required.

### Refresh policy

- **README.md / README_CN.md / AGENTS.md**: keep existing structure; replace the "UpUp's Additions" block with a pointer to the white paper; add a "8-dimension China-edition advantage" callout.
- **docs/comparison.md**: keep the TL;DR table; replace the "vs virattt/dexter" table's numbers with citations to the audit doc; keep the "vs Claude Code" / "vs Aider" / "vs Cursor" sections.
- **docs/positioning.md**: keep the "10 sections" structure; replace section 9 (vs competitors) with a link to `docs/COMPETITIVE.md`; section 1–8 stay.
- **docs/COMPETITIVE.md**: keep the 13-competitor × 7-dimension matrix; drop the "vs dexter" duplicate section (move to `docs/comparison.md`).
- **docs/GAP-ANALYSIS.md / docs/AI-AGENT-GAP-ANALYSIS.md**: prepend a one-line "Superseded by docs/upup-vs-dexter-audit.md (2026-06-12); kept for historical reference."
- **CHANGELOG.md**: append to `[Unreleased]` a single entry: "Doc refresh: authoritative upup-vs-dexter audit + China-edition white paper; aligned README/AGENTS/comparison/positioning/COMPETITIVE."

### Out of scope (intentionally)

- No CI script to regenerate the audit (left as a follow-up change `audit-ci-automation`).
- No automated test that fails the build on stale numbers (left as a follow-up).
- No translation of the white paper into English (the white paper is intentionally Chinese; English positioning lives in README.md).

## Risks & Open Questions

- **Risk: numbers go stale.** The audit doc is dated and references HEAD; we accept that "as of 2026-06-12" means readers need to re-run the methodology. The spec defines the regen command but does not enforce CI. *Mitigation:* add `audit-ci-automation` as a follow-up change.
- **Risk: doc rot via duplicated prose.** Several docs still have their own "vs dexter" mini-section. *Mitigation:* this change's tasks explicitly call out deletion of duplicated paragraphs.
- **Open question: white paper language.** Intentionally Chinese only. If English speakers ask for an EN version, that becomes a follow-up change.
- **Open question: CHANGELOG entry size.** Keeping a single Unreleased entry for the whole doc refresh; if reviewers want a per-doc changelog, easy to split later.
