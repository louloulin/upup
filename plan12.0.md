## 📊 Claude Code vs UpUp 记忆系统详细对比

### Claude Code 记忆架构

```
~/.claude/projects/<slug>/memory/
├── MEMORY.md                    # 索引入口 (200行限制)
├── user/                        # 用户私人记忆
│   ├── user_role.md
│   └── feedback_testing.md
├── feedback/                    # 用户反馈记忆
├── project/                     # 项目记忆
└── reference/                  # 外部引用记忆

~/.claude/projects/<slug>/memory/team/  # Team 记忆 (可选)
├── MEMORY.md
├── user/
├── feedback/
├── project/
└── reference/
```

### UpUp 当前记忆架构

```
~/.upup/memory/
├── MEMORY.md                    # 索引入口
├── user/                        # 用户记忆
│   └── *.md
├── feedback/                    # 反馈记忆
│   └── *.md
├── project/                     # 项目记忆
│   └── *.md
└── reference/                   # 引用记忆
    └── *.md
```

### 差异分析

| 功能 | Claude Code | UpUp | 说明 |
|------|-------------|------|------|
| Team Memory | 独立 `team/` 目录 | 无 | Claude Code 支持团队协作 |
| 记忆隔离 | auto/team 双目录 | 单目录 | 项目级隔离不足 |
| 会话记忆 | 追加到 daily log | 通过 extraction | 机制不同 |
| KAIROS 模式 | 支持 daily log | 不支持 | Claude Code 高级功能 |

### 3. 记忆系统架构 (2-Phase)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         记忆系统 2-Phase 架构                                │
└─────────────────────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                     Phase 1: Per-Turn Extraction                        │
  │  触发时机: 模型生成最终响应后 (无 tool_calls)                            │
  └──────────────────────────────────┬──────────────────────────────────────┘
                                     │
                                     ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                           Memory Extraction                               │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  输入: [user message, assistant response, ...]                   │  │
  │  │  过程: LLM 分析对话，识别值得保存的信息                            │  │
  │  │  输出: ExtractionResult[] (name, description, type, content)     │  │
  │  └──────────────────────────────────────────────────────────────────┘  │
  │                               │                                          │
  │                               ▼                                          │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  验证: Zod Schema (MEMORY_FRONTMATTER_SCHEMA)                   │  │
  │  └──────────────────────────────────────────────────────────────────┘  │
  │                               │                                          │
  │                               ▼                                          │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  写入: <type>/<name>.md with frontmatter                         │  │
  │  │  ├── name: <name>                                               │  │
  │  │  ├── description: <description>                                 │  │
  │  │  ├── type: <user|feedback|project|reference>                     │  │
  │  │  └── content: <memory content>                                   │  │
  │  └──────────────────────────────────────────────────────────────────┘  │
  │                               │                                          │
  │                               ▼                                          │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  更新: MEMORY.md index                                           │  │
  │  │  格式: - [type/name.md](type/name.md) — description              │  │
  │  └──────────────────────────────────────────────────────────────────┘  │
  └─────────────────────────────────────────────────────────────────────────┘

                                     │
                                     ▼ (定时 24h 或 5+ 新会话)

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                    Phase 2: Periodic Consolidation                       │
  │  触发时机: 每 24h 或 5+ 新会话后                                         │
  └──────────────────────────────────┬──────────────────────────────────────┘
                                     │
                                     ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                        Memory Consolidation                             │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  1. 获取锁 (.consolidation.lock) 防止并发                        │  │
  │  │  2. 读取所有 memory 文件                                          │  │
  │  │  3. 按 topic 分组 (name 前缀)                                     │  │
  │  │  4. 找出可合并的组 (文件数 > 1)                                   │  │
  │  │  5. LLM 合并相似主题                                              │  │
  │  │  6. 删除旧文件，写入新文件                                        │  │
  │  │  7. 更新 MEMORY.md                                               │  │
  │  │  8. 释放锁                                                        │  │
  │  └──────────────────────────────────────────────────────────────────┘  │
  └─────────────────────────────────────────────────────────────────────────┘

  合并决策:
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                          LLM Consolidation Output                        │
  │  {                                                                       │
  │    "merged_memories": [                                                  │
  │      { "name": "...", "type": "...", "content": "...", "merge_from": [] },│
  │    ],                                                                    │
  │    "delete_files": ["..."]                                               │
  │  }                                                                       │
  └─────────────────────────────────────────────────────────────────────────┘
```

## 🔍 问题分析

### 问题 1: Build 错误 - 缺少 @types/glob

```
error TS2688: Cannot find type definition file for 'glob'.
```

**解决方案**: 在 tsconfig.json 中添加 `"skipLibCheck": true` 或安装 `@types/glob`

### 问题 2: 记忆隔离不足

**现状**: UpUp 只有单目录记忆，无法区分私人/团队记忆

**解决方案**: 实现双目录架构 (参考 Claude Code 的 auto/team 分隔)

### 问题 3: 缺少 Team Memory 支持

**现状**: 不支持团队协作记忆

**解决方案**: 实现 `~/.upup/projects/<slug>/memory/team/` 目录
