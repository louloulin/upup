## 二、剩余 root runtime 迁移矩阵

| Root 模块 | 当前 | 目标 | 收口条件 |
|---|---|---|---|
| `agent-session-factory.ts` | 唯一 Session composition root | 保留为唯一 root factory | 只组合 Package catalog/capability，不新增业务分支 |
| `runner.ts` | root Pi session runner | 保留为唯一 runner | 所有入口通过此 runner |
| `agent-spec.ts` | root profile/spec 定义 | `@upup/pi-investment-workflow` 或 runtime contract | profiles 可序列化且无重复 registry |
| `registry.ts` / `agent-catalog.ts` | root agent catalog | `@upup/pi-runtime` 或 workflow package | 无第二套 AgentDefinition store |
| `agent-port.ts` | root port 类型/显式 runtime port | `@upup/pi-runtime` contract | 无 globalThis fallback |
| `tool.ts` | root PiTool 兼容类型 | `@upup/pi-runtime` contract | 无独立 tool registry |
| `prompts.ts` | root prompt assembly | `@upup/pi-app` / prompt package | 只注入 Package resources 与 session context |
| `investment-workflow.ts` | 87 行 root factory bridge | `@upup/pi-app` composition | Package 不反向 import root |
| `bootstrap.ts` | 入口 bootstrap | `@upup/pi-app` | CLI/stdio/gateway/bridge 共享 bootstrap |
| `index.ts` | root compatibility barrel | 删除或只保留公开 runtime contract | 生产消费者为零后删除 |

## 三、阶段计划

### 阶段 A：修复验证缺口

1. 修复并稳定复现 `packages/pi-bridge/src/session-sync.e2e.test.ts` 的 WebSocket timeout/race。
2. 为 `PiPromptPort` 增加 isolation、未 bootstrap fail-closed、重复 bootstrap 幂等测试。
3. 为 `@upup/pi-event-adapter` 的 `streamPiAgentWithRunner` 增加 injected-runner contract test。
4. 更新门禁，检查 Package → root `src` 反向依赖和所有新增动态 import。

### 阶段 B：runtime contract 下沉

1. 将 `agent-port.ts` 的公共 port 类型下沉到 `@upup/pi-runtime`，root 仅保留 wiring。
2. 将 `tool.ts` 的公共 PiTool contract 下沉到 `@upup/pi-runtime`，删除 root compatibility implementation。
3. 将 `agent-catalog.ts` 与 `registry.ts` 的可序列化 catalog 能力下沉到既有 runtime/workflow package；删除重复 store。
4. 评估 `agent-spec.ts` 的 Profile 定义归属，确保 `@upup/pi-investment-workflow` 是投资 profile 的唯一 owner。

### 阶段 C：入口与资源最终收口

1. 将 prompt assembly 与 workflow factory bridge 收口到 `@upup/pi-app`（仅在明确边界成立时新增 package）。
2. 将 root `src/runtime/pi/index.ts` 改为最小 public contract barrel，删除无消费者 re-export。
3. 将 `src/evals`、`src/management`、`src/print.ts` 改为 Package API + root bootstrap，不直接读取 runtime 私有模块。
4. 强化 root allowlist 静态检查：仅允许 `src/index.tsx`、`src/cli.ts`、`src/compat/**`、`src/bootstrap/**` 与登记的必要 migration/bridge。

## 四、完成定义

只有同时满足以下条件，才能把 Pi10/Pi7 标记为完成：

- 唯一 `createAgentSession`/AgentSession factory。
- 所有能力通过 Pi Package manifest、extension、capability context 接入。
- 无生产 `legacy-events`、globalThis registry、重复 tool/skill/agent registry。
- root `src` 无金融业务、工具实现、技能 loader、MCP 实现或独立 Agent loop。
- CLI、Gateway、Bridge、stdio、Cron、Daemon、SDK、Eval 共用 Pi Runtime。
- `/invest` 五阶段可恢复、证据可追溯、风险可审计、副作用默认 sandbox/deny/approval。
- 静态门禁、Package contract、全仓测试、构建和所有入口 smoke 通过。
- 真实 provider 结果与本地 fixture 结果分开记录。

当前判断：核心架构已达到 99.95% 级别；尚未达到 100%，原因是 session-sync race、root runtime contract 仍有少量核心实现、真实 provider smoke 缺少凭证证据。
